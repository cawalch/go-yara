`go-yara` compiles YARA rules and scans byte slices, readers, and files in Go. It runs without CGO or an installed copy of libyara, so you can include the engine in a Go service or build a standalone scanner.

[Compile a rule and scan your first input](/go-yara/quickstart/), or [install the CLI](/go-yara/installation/) to work with files.

## Where it fits

Use the library when your application already handles the data: a file ingestion service, an artifact scanner, or a tool that applies rules to collected memory blocks. Compile a rule set once and reuse the program across scans. Host modules let your rules inspect application data alongside the input bytes.

The engine supports text strings, hex patterns, regular expressions, and the built-in `hash`, `math`, `string`, and `time` modules. It also provides structured host modules and optional evidence extraction.

## Check your rules before migrating

YARA implementations differ. Native `pe` and `elf` parsers are not bundled, and go-yara has extensions that libyara does not accept. The [compatibility guide](/go-yara/compatibility/) identifies those boundaries. Test your rule corpus and expected matches before replacing another engine.

Reader and block APIs have different memory and condition-evaluation behavior. Read [choosing a scan API](/go-yara/scanning/#choose-an-input-api) before using them for large inputs.
