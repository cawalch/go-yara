## Changes in v0.10.1

v0.10.1 fixes `v0.10.0` high-EPS compact-prefilter, `ruleResultsDense` clear, and hot-path `defer` regressions on mixed literal/regex/hex corpora (see [v0.10.1 performance changes](/go-yara/performance/#v0101-performance-changes)), adds zero-allocation contracts and a CI `benchstat` regression gate (`scripts/perf_gate.sh`) ([#536](https://github.com/cawalch/go-yara/pull/536)), and updates the module catalog generator probe for built-in functions ([#534](https://github.com/cawalch/go-yara/pull/534)). Compiled artifact **format 20** and the **Go 1.27.0** minimum toolchain requirement are unchanged from `v0.10.0`.

## Upgrade to v0.10.0

{release.format < 20 && <p><strong>Not yet released.</strong> These notes describe the planned v0.10.0 release. The installation commands and playground still use the published {release.version} release.</p>}

v0.10.0 raises the minimum toolchain requirement to **Go 1.27.0**, adds a pure-Go `pe` module backed by `go-pe`, introduces borrowed evidence (`WithBorrowedEvidence`) and reflection-free streaming JSON encoders, adds `WithStrictLibyaraCompatibility(true)` and `of`/`for` expression quantifiers, makes `MarshalBinary` / `WriteTo` byte-deterministic, and adds compiled-artifact validation (`ErrCorruptProgram`) alongside prefilter and verification hotpath optimizations.

New compiled artifacts use **format 20** (adding `ModuleRegex` / `OpPushRegex` in format 19 and deterministic sorted map encodings in format 20). The reader accepts formats **4–20**, while `v0.9.0` writes format **18** and cannot read format **20** artifacts. Recompile rules from source to gain deterministic serialization digests and artifact integrity checks, and keep separate caches during rollout and rollback.

Native `elf`, `cuckoo`, and `dotnet` modules and general cyclic combined-NFA execution remain outside this release. Rules matching `pe.imphash()` should guard with `pe.number_of_imports > 0` when import-less binaries must not match on `md5("")`. See the [v0.10.0 performance notes](/go-yara/performance/#v0100-performance-changes) for scope and tradeoffs.

## Changes in v0.9.0

v0.9.0 focuses on regex occurrence correctness, streaming boundaries and read errors, lower evidence allocation, and faster compilation. Regex fixes cover greedy/lazy repetition, alternatives, anchors, wide/fullword matching, and verification bounds. Compare counts, offsets, lengths, and final rule outcomes when upgrading; a boolean-only check can miss a changed occurrence.

v0.9.0 compiled artifacts use format **18**, compared with format **7** in v0.8.2; legacy unbounded regex artifacts without a finite verification horizon need recompilation or an explicit `WithMaxMatchSpan` for reader scans. Prebuilt CLI binaries use the default build; optional SIMD acceleration uses `GOEXPERIMENT=simd`. See the [v0.9.0 performance changes](/go-yara/performance/#v090-performance-changes) for eligibility limits.

## Changes in v0.8.2

v0.8.2 upgrades `ScanReader` and `ScanReaderWithContext` to use constant-memory streaming ($C + W$) with full rule condition evaluation, eliminating unbounded buffer slurping (`io.ReadAll`) on large streams ([#352](https://github.com/cawalch/go-yara/issues/352)). It introduces `MatchesReader` for early-exit boolean matching. The input window is bounded independently of stream length; retained occurrences, result data, and evidence can still grow with matches.

## Changes in v0.8.1

v0.8.1 fills the scan phase timers and dispatches per-pattern profiles. Completion hooks now see final telemetry, and detailed, boolean, rule-list, and block scans use consistent accounting. `PatternProfile.CandidateHitsKnown` distinguishes unavailable candidate counts from zero hits. If you export these fields, review the [metric definitions](/go-yara/performance/#hooks-and-scan-metrics): loop steps count per-rule iterations, and candidate counts describe logical rule contexts rather than physical verifier calls.

The Go requirement and serialized program format are unchanged from v0.8.0.

## Documentation versions

The site rebuilds when a release is published or `main` changes. Version details, module signatures, the serialized format number, and CLI help come from the latest stable release. The displayed Go and CLI examples run against that release and the current source tree before deployment.

Behavioral explanations still need review when code changes. Deployment waits for a recorded prose review of each release. The repository's [documentation maintenance guide](https://github.com/cawalch/go-yara/blob/main/site/README.md) maps code changes to pages, and its [writing guide](https://github.com/cawalch/go-yara/blob/main/site/WRITING.md) records the editorial standard.
