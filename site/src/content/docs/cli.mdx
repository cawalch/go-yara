## Validate rules and inspect output

To compile without scanning a target:

```sh
go-yara greeting.yar --mode=compile
```

Use `--mode=lex` to inspect tokens or `--mode=parse` to inspect the parsed rule structure. For scan output, `-s` includes matching strings, `-g` includes tags, and `-m` includes metadata. `--json` produces structured records suitable for downstream tools. Place options before a positional target.

For a directory, use `-r` to recurse and `-p` to choose the worker count. Rule and tag filters select which results are reported; see the generated help below for their names.

## Large files and streaming

`--streaming` is a literal text-pattern reporting mode. It does not evaluate complete rule conditions. It is not equivalent to a normal scan with lower memory use, and it does not provide regex or hex-pattern rule evaluation.

Use it only when literal occurrences are sufficient. `--chunk-size` controls chunked I/O; it does not add full-condition semantics. For normal rule evaluation, plan for the input memory required by the scan API.
