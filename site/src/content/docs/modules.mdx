## Function arguments

Hash functions accept either a string or an `(offset, size)` range in the scanned input. They return a digest string, except `crc32` and `checksum32`, which return integers.

The statistical functions accept strings or input ranges. `math.count` and `math.percentage` take a byte value, optionally followed by an offset and size. `math.mode` accepts an optional offset and size. `math.in_range(value, lower, upper)` takes three floats and returns an integer truth value.

`math.deviation(offset, size, mean)` and `math.deviation(string, mean)` calculate mean absolute deviation. The two-integer form is the go-yara standard-deviation extension. `math.to_string` accepts an optional base of 8, 10, or 16. `string.to_int` accepts an optional integer base; invalid conversions produce undefined.

Invalid ranges also produce undefined. Ranges starting inside the input are truncated at EOF. See [numeric and string differences](/go-yara/compatibility/#numeric-and-string-behavior) for unsigned comparisons, float overloads, and high-byte statistics.

Schemas can contain nested structures, arrays, string-keyed dictionaries, and scalar constants. Bind exported Go struct fields, string-keyed maps, slices, or arrays. Field names are case-insensitive for Go structs unless an exact `yara:"name"` tag is provided. Values must match the declared schema.

Missing fields, missing dictionary keys, and out-of-range array indices evaluate as undefined. Use `defined` when the condition requires a value. Missing collections iterate as empty collections: `any` is false, while `all` and `none` are true.

`WithModuleData` reports binding errors through scan methods. To replace data between scans and receive an error immediately, call `scanner.SetModuleData(name, data)`. Binding copies the data; setters must not run concurrently with scans.

`ModuleContext` supplies scan data, blocks, and the current rule name; it is not a `context.Context`. This example operates on ordinary byte-slice scans. A callback intended for sparse block scans must implement the address semantics it needs using the supplied blocks. Keep callbacks bounded and avoid blocking I/O: scanner cancellation cannot preempt Go code that is blocked inside your callback.

Return `ModuleValue{}` for undefined. An undefined argument propagates without invoking the callback; a non-nil callback error fails the scan. For cache opt-in, results must depend only on input data, blocks, and arguments, never the rule name, time, external state, or side effects. String arguments are not eligible for this cache.

Deterministic built-in numeric and range calls share a bounded cache within each scan. String arguments and `time.now()` are not cached. Custom callbacks are uncached unless they opt in with `ModuleFunction.Cacheable` and satisfy its purity contract. A digest calculation can still allocate on a cache miss; see [performance](/go-yara/performance/#module-call-cache).

Pass custom handlers to `UnmarshalCompiledProgram` while loading, then bind host data again. Schemas survive serialization; runtime data does not.
