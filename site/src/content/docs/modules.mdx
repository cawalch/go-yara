Use the built-in `pcap` module for TLS certificate-name comparisons. For DNS and HTTP fields, the Go examples decode records with go-pcap and pass the selected fields to YARA while retaining packet and flow evidence.

### Compare TLS certificate names

The checked-in rules compare each flow's ClientHello SNI with the server leaf certificate's DNS names:

<Code code={tlsRules} lang="text" title="examples/pcap/tls.yar" />

```sh
go mod download github.com/cawalch/go-pcap
fixtures="$(go list -m -f '{{.Dir}}' github.com/cawalch/go-pcap)/testdata/deployments"
go run ./cmd examples/pcap/tls.yar "$fixtures/proxy.pcapng"
```

The synthetic proxy capture matches only `tls_name_evidence_missing`: its TLS 1.3 handshakes have no keys to recover the leaf certificates. A defined false comparison indicates a name mismatch; undefined means the comparison lacks evidence, including missing SNI, a missing leaf, or a potentially omitted SAN at the parser limit. Neither result establishes certificate trust or malicious activity.

TLS extraction runs on first evaluated access to `pcap.tls` and is reused within the scan. Invalid captures, parser errors, or inputs larger than 64 MiB make the array undefined. For streaming, use an `io.ReaderAt` and `io.Seeker`, such as an open file; sequential-only inputs must fit completely in the retained 64 KiB header. See [capture limits and flow indices](https://github.com/cawalch/go-yara/blob/main/docs/pcap-module.md#capture-and-reader-limits).

### Find DNS questions and paired failures

Run the DNS watch adapter against the synthetic IoT capture using the `fixtures` variable above:

```sh
go run ./examples/pcap/dns-watch "$fixtures/iot.pcapng"
```

```text
watched_dns_question packet=2 flow=2 name="collector.example"
```

Packet and flow indices are zero-based; inspect frame 3 in a packet viewer. This finding establishes a DNS question, not a completed connection.

The required-service adapter pairs questions and replies, then scans the complete question name with the response code as an external integer:

```sh
go run ./examples/pcap/dns-failure ./examples/pcap/dns-failure/testdata/service.pcap
```

```text
required_service_dns_failure name="api.example" resolver=192.0.2.53:53 rcode=3 query_frame=1 reply_frame=2
required_service_dns_failure name="api.example" resolver=192.0.2.53:53 rcode=2 query_frame=3 reply_frame=4
```

Inspect frame 2 for NXDOMAIN and frame 4 for SERVFAIL. Edit `$service` in the [required-service rule](https://github.com/cawalch/go-yara/blob/main/examples/pcap/dns-failure/required-service.yar) to watch another name. Pairing requires ordinary single-question DNS on port 53 from one observation point; repeated identical outstanding questions make the pairing key ambiguous for the rest of the capture. See the [Go adapter and DNS examples](https://github.com/cawalch/go-yara/blob/main/docs/pcap-module.md#investigate-a-required-service-that-fails-to-resolve).

### Hunt decoded HTTP requests

The HTTP adapter applies inventory and approval policies to decoded HTTP/1 and HTTP/2 requests:

```sh
go run ./examples/pcap/http-hunts ./examples/pcap/http-hunts/testdata/hunts.pcap
```

```text
unexpected_server_webhook_post frame=2 time_ns=1700000000002469134 flow=0 stream=0 source=192.0.2.10 POST webhook.site
unapproved_decoy_route_access frame=11 time_ns=1700000000013580237 flow=5 stream=3 source=192.0.2.12 GET app.example
```

Frames identify the start of each request, even when it spans packets; stream zero denotes HTTP/1. Replace the fixture's source inventory, webhook approvals, and private decoy route before using a real capture. Unknown sources produce no findings. Encrypted-only traffic cannot establish an HTTP method or route from SNI. A webhook POST establishes an attempted transfer; acceptance and contents require separate evidence. See [HTTP rules, benign controls, and packet attribution](https://github.com/cawalch/go-yara/blob/main/docs/http-capture-hunts.md).

## Function arguments

Hash functions accept either a string or an `(offset, size)` range in the scanned input. They return a digest string, except `crc32` and `checksum32`, which return integers.

The statistical functions accept strings or input ranges. `math.count` and `math.percentage` take a byte value, optionally followed by an offset and size. `math.mode` accepts an optional offset and size. `math.in_range(value, lower, upper)` takes three floats and returns an integer truth value.

`math.deviation(offset, size, mean)` and `math.deviation(string, mean)` calculate mean absolute deviation. The two-integer form is the go-yara standard-deviation extension. `math.to_string` accepts an optional base of 8, 10, or 16. `string.to_int` accepts an optional integer base; invalid conversions produce undefined.

Invalid ranges also produce undefined. Ranges starting inside the input are truncated at EOF. See [numeric and string differences](/go-yara/compatibility/#numeric-and-string-behavior) for unsigned comparisons, float overloads, and high-byte statistics.

Declare the shape of application data with `Module.Schema`. The compiler checks member names and types; each scanner receives its own data snapshot.

Schemas can contain nested structures, arrays, string-keyed dictionaries, and scalar constants. Bind exported Go struct fields, string-keyed maps, slices, or arrays. Field names are case-insensitive for Go structs unless an exact `yara:"name"` tag is provided. Values must match the declared schema.

Missing fields, missing dictionary keys, and out-of-range array indices evaluate as undefined. Use `defined` when the condition requires a value. Missing collections iterate as empty collections: `any` is false, while `all` and `none` are true.

`WithModuleData` reports binding errors through scan methods. To replace data between scans and receive an error immediately, call `scanner.SetModuleData(name, data)`. Binding copies the data; setters must not run concurrently with scans.

`ModuleContext` supplies scan data, blocks, and the current rule name; it is not a `context.Context`. This example operates on ordinary byte-slice scans. A callback intended for sparse block scans must implement the address semantics it needs using the supplied blocks. Keep callbacks bounded and avoid blocking I/O: scanner cancellation cannot preempt Go code that is blocked inside your callback.

Return `ModuleValue{}` for undefined. An undefined argument propagates without invoking the callback; a non-nil callback error fails the scan. For cache opt-in, results must depend only on input data, blocks, and arguments, never the rule name, time, external state, or side effects. String arguments are not eligible for this cache.

Deterministic built-in numeric and range calls share a bounded cache within each scan. String arguments and `time.now()` are not cached. Custom callbacks are uncached unless they opt in with `ModuleFunction.Cacheable` and satisfy its purity contract. A digest calculation can still allocate on a cache miss; see [performance](/go-yara/performance/#module-call-cache).

Pass custom handlers to `UnmarshalCompiledProgram` while loading, then bind host data again. Schemas survive serialization; runtime data does not.
