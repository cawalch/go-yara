### Review an update detection rule

A responder has a revoked build identifier and a proxy capture. The baseline checks for the update request and the identifier anywhere among the capture's HTTP transactions. The candidate requires both in one confirmed transaction with a complete response body. The control contains a legitimate update and the identifier in an unrelated diagnostics response.

<PCAPReview />

The preview runs the Go scanner and go-pcap decoder in a local worker. Capture bytes stay in the browser. Edit either rule or choose a local PCAP or PcapNG up to 1 MiB. The control should remove `revoked_update`. Both revisions match the update containing the identifier and independently report the observed DNS answer.

```sh
fixture=examples/pcap/update-review
go run ./cmd/compare -baseline "$fixture/baseline.yar" -candidate "$fixture/candidate.yar" \
  positive="$fixture/positive.pcap" control="$fixture/control.pcap"
```

The JSON report contains added and removed rule names, fixture digests, and compiled-rule digests. Capture packet indices locate the observed exchange. Decoded body bytes have their own offsets. [Packet capture fields](https://github.com/cawalch/go-yara/blob/main/docs/pcap-module.md)

Use the versioned manifest to also check which exchange supports a match. Each fixture pins its capture digest and names a public rule in both revisions.

```sh
go run ./cmd/compare -baseline "$fixture/baseline.yar" -candidate "$fixture/candidate.yar" \
  -expect "$fixture/corpus.json" positive="$fixture/positive.pcap" control="$fixture/control.pcap" \
  split="$fixture/positive-split.pcap" unavailable="$fixture/unavailable.pcap"
```

The control removes `revoked_update` from the candidate. The split request has the same decoded evidence as the positive capture and a different response packet index. The clipped response is unobservable. The built comparator exits with `2` for a mismatch and `1` for an execution failure.

`http` mode tests each complete response row in isolation within the original capture context. A rule that matches with no rows, or requires multiple rows, can report a match with an empty evidence list. `artifact` mode runs file rules on complete decoded responses and compares entity-relative match spans. For external variables, supply a non-secret `-binding-revision` alongside `-externals`.

### Capture fields and coverage

- `pcap.http` holds cleartext HTTP/1 rows. Use `pairing`, the body states, and `packets` to assess and locate evidence. Header arrays retain duplicates in wire order.
- `pcap.dns` holds unicast DNS rows on TCP or UDP port 53. Each row exposes `pairing` and the observed `query` or `reply`. Use the record's `complete` field and original packet index when interpreting answers.
- `pcap.tls` exposes flow indices and observed TLS certificate name agreement. Undefined name agreement means the comparison lacks evidence.

Extraction runs on first evaluated access to each collection. An undefined collection means the input or scan could not supply it. `pcap.capture_truncated` identifies a captured container with an incomplete tail. Check the capture point and decoded row coverage when interpreting absence. [TLS triage and capture limits](https://github.com/cawalch/go-yara/blob/main/docs/pcap-module.md)

## Function arguments

Hash functions accept either a string or an `(offset, size)` range in the scanned input. They return a digest string, except `crc32` and `checksum32`, which return integers.

The statistical functions accept strings or input ranges. `math.count` and `math.percentage` take a byte value, optionally followed by an offset and size. `math.mode` accepts an optional offset and size. `math.in_range(value, lower, upper)` takes three floats and returns an integer truth value.

`math.deviation(offset, size, mean)` and `math.deviation(string, mean)` calculate mean absolute deviation. The two-integer form is the go-yara standard-deviation extension. `math.to_string` accepts an optional base of 8, 10, or 16. `string.to_int` accepts an optional integer base; invalid conversions produce undefined.

Invalid ranges also produce undefined. Ranges starting inside the input are truncated at EOF. See [numeric and string differences](/go-yara/compatibility/#numeric-and-string-behavior) for unsigned comparisons, float overloads, and high-byte statistics.

## Bind structured data

Declare the shape of application data with `Module.Schema`. The compiler checks member names and types; each scanner receives its own data snapshot.

Schemas can contain nested structures, arrays, string-keyed dictionaries, and scalar constants. Bind exported Go struct fields, string-keyed maps, slices, or arrays. Field names are case-insensitive for Go structs unless an exact `yara:"name"` tag is provided. Values must match the declared schema.

Missing fields, missing dictionary keys, and out-of-range array indices evaluate as undefined. Use `defined` when the condition requires a value. Missing collections iterate as empty collections: `any` is false, while `all` and `none` are true.

`WithModuleData` reports binding errors through scan methods. To replace data between scans and receive an error immediately, call `scanner.SetModuleData(name, data)`. Binding copies the data; setters must not run concurrently with scans.

`ModuleContext` supplies scan data, blocks, and the current rule name; it is not a `context.Context`. This example operates on ordinary byte-slice scans. A callback intended for sparse block scans must implement the address semantics it needs using the supplied blocks. Keep callbacks bounded and avoid blocking I/O: scanner cancellation cannot preempt Go code that is blocked inside your callback.

Return `ModuleValue{}` for undefined. An undefined argument propagates without invoking the callback; a non-nil callback error fails the scan. For cache opt-in, results must depend only on input data, blocks, and arguments, never the rule name, time, external state, or side effects. String arguments are not eligible for this cache.

Deterministic built-in numeric and range calls share a bounded cache within each scan. String arguments and `time.now()` are not cached. Custom callbacks are uncached unless they opt in with `ModuleFunction.Cacheable` and satisfy its purity contract. A digest calculation can still allocate on a cache miss; see [performance](/go-yara/performance/#module-call-cache).

Pass custom handlers to `UnmarshalCompiledProgram` while loading, then bind host data again. Schemas survive serialization; runtime data does not.
