## Reuse the program

Keep the compiled program when scanning more than one input. Its convenience methods manage pooled scanners, and the program supports concurrent scans. For custom options or repeated scans in one worker, [create a reusable scanner](/go-yara/scanning/#reuse-a-scanner).

## Compile files and inspect rejected rules

Use `CompileFileWithContext(ctx, path)` for a rule file. Relative `include` paths resolve from the containing file's directory. For source strings containing relative includes, set the compiler's base directory with `SetBaseDir` before compilation. `import` makes a registered module namespace available to the rules; `include` loads another rule file.

Compilation normally fails on an invalid rule. For an ingestion workflow that deliberately accepts a reduced rule set, `WithIgnoreInvalidRules(true)` keeps valid rules and reports omissions through `GetIgnoredRules`. Dependencies on rejected rules are omitted too; an invalid global rule can therefore remove otherwise valid rules. Fatal program-level errors still return an error.

## Semantic analysis and diagnostics

Compilation checks the meaning of a parsed rule before producing an executable program. The semantic layer resolves identifiers and rule references, checks operator and function argument types, validates module fields against registered schemas, and rejects circular rule dependencies. Capture-group references and evidence declarations are checked here too.

<ArchitectureDiagram kind="semantic" />

Forward references to other rules are allowed; dependency cycles are rejected. A well-typed rule can still encounter undefined values when it runs. For example, `string.to_int("oops")` is a valid function call whose result is undefined. Use `defined` when the condition needs to distinguish that case. Semantic analysis does not inspect future input bytes or establish whether an extracted credential works.

`Compiler.GetErrors()` exposes compiler diagnostics with `Phase`, `Code`, `Message`, `Line`, and `Column`. For semantic failures, the returned error wraps the first `semantic.Error`; `errors.As` retrieves its code, position, rule, and optional suggestion. Use structured codes for classification and the message for display. Parsing and later compilation failures do not necessarily wrap a semantic error.

Most applications should compile through `compiler`, which resolves includes and supplies the registered module signatures and schemas to the validator. The exported `semantic.Validator` also accepts an AST for tooling that already owns one. A standalone validator needs the applicable module definitions; `semantic.NewValidator()` does not populate the compiler's built-in module registry.
