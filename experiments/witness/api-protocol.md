# Public API routing study

Frozen before API timing. Compare one compiled YARA program through `NewScanner(WithFastScan())` and `NewScanner(WithFastScan(), WithBooleanRouting())`. Both measured paths call `scanner.Matches` directly and check every result against the fixture's static truth. Prototype matchers are compiled only because the unchanged historical fixture package imports them; they are never invoked by these API benchmarks.

The original 32 routing fixtures are byte-identical to the frozen research corpus. Nine 256-byte, 1%-positive literal/conjunction/complex cases at 24/256/2,048 rules remain primary. All other cases remain guards, including short patterns, repeated near misses, fixed contexts, binary data, and 4/64KiB records. An independently named supplemental matrix adds 12 all-positive 256-byte cases: literal, complex, shared tail and shared context at all three rule counts. These supplement rather than replace the 32 original cases.

Each scan variant warms and validates all 100 fixture events before timing. Six fresh-process 100ms rounds alternate variant order; primary and supplemental logs stay separate. Report per-case median latency, allocation counts, paired benchstat and primary/family geometric means. Acceptance remains at least 10% primary aggregate improvement, improvement in each primary family, no selected-plan guard over 10% slower than baseline, and no declined or size-bypassed guard over 5% slower. Apply the same guard budgets to the 12 supplemental positive cases. Correctness, complete six-sample evidence and active plans for all nine primary cases are required. No fixture or threshold retuning after measurements.

Plan activation is read through study-only reflection outside timing and logged as `plan_active/op`; `size_bypass/op` distinguishes the API's >1,024-byte bypass. Reflection reads only whether the private scanner plan pointer is nil. The API's internal Unknown count is unavailable; timings include any fallback without asserting a measured fallback rate. Exact YARA source conversion may alter eligibility: notably frozen nocase literals become explicit `[Aa]` classes rather than a nocase modifier. Report actual API activation, not prototype eligibility.

Startup uses complex/shared-tail/shared-context portfolios at all three rule counts. Six first-scanner samples time only `NewScanner` on a fresh normally compiled program; source compilation and `Close` are excluded. Cached-plan samples initialize once, then time 100 `NewScanner` calls sharing that program. Their storage is preallocated and all scanners are closed outside timing. Scanner allocations remain measured. Startup is report-only; the experiment does not impose a new startup gate.

Go 1.26.0, Linux amd64, GOAMD64=v1, GOMAXPROCS=2; exact HEAD, source and binary hashes, CPU, validation logs and every raw sample are uploaded. Repository tests, focused race/vet and all 44 API parity cases precede timing. A passing result supports opt-in integration only; it does not enable routing by default.

Limits: synthetic logs rather than customer traffic; eight layouts and rotating boundaries share generated marker families. Large records mostly contain space padding and are bypass controls, not representative large-event performance. Both variants use the same new compiler, so this isolates opt-in behavior, not the metadata/compilation overhead versus an older release. The original prototype study remains historical evidence; its measured code and this public API are different treatments. The API does not provide runtime decision counters or retained-memory reporting in this study.
