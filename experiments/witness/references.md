# Word-witness detector: prior art and falsifiable predictions

Reviewed 2026-09-19. Scope: byte-oriented, many-pattern search on small mostly-negative records; literal anchors plus exact bounded-gap/class/alternative verification. Nine primary papers or implementation documents below were checked directly through public publisher, author, institutional, or project sources. This is a bounded review, not an exhaustive novelty search or a claim of current state of the art. No measurements were performed for this review.

## Assessment

The proposed all-alignments, strided q-word filter belongs to established sampled q-gram filtering. Its exact coverage condition already appears in q-sample indexing [1]; multi-pattern work explicitly handles every pattern shift when consuming non-overlapping text q-grams [2]. Reversing which side is indexed and specializing the table for short event records can be useful engineering, but does not establish a new search principle. Removing a general regex VM also does not make the approach unprecedented: decomposed matching, bit-parallel predicates and positional verification have substantial prior art [2,5,7].

## Verified references

1. **Johannes A. Krugel, Approximate Pattern Matching with Index Structures (2016), §2.4.2, printed pp.60–61.** [Institutional dissertation PDF](https://mediatum.ub.tum.de/doc/1251902/859908.pdf). Describes q-sample indexes, the guarantee `m >= q + stepSize - 1`, looking up pattern q-grams and verifying candidate positions. Closest explicit coverage argument found. Its indexed-text setting differs from this proposed online, indexed-pattern implementation.

2. **Susik, Grabowski, Fredriksson, Multiple Pattern Matching Revisited (2014), §§2–3.** [Author preprint](https://arxiv.org/abs/1405.5483). Combines q-grams, superimposition, bit-parallelism and alphabet reduction. Non-overlapping q-grams require all q pattern shifts; character sampling trades fewer examined positions for verification work. Covers the core alignment and filtering family, though not this exact table layout. Shift-Or style bitsets offer a compact class-aware competitor when its superimposed alphabet remains selective.

3. **Wu and Manber, A Fast Algorithm for Multi-Pattern Searching (1994), §2.** [University technical report](https://www.cs.arizona.edu/sites/default/files/TR94-17.pdf). Uses hashed short blocks for safe shifts, candidate lists and prefix checks before full comparison. Hash collisions shorten permissible shifts instead of losing matches. Strong scalar competitor: adaptive skips can exceed a fixed stride when patterns are long and negative blocks are informative.

4. **Faro and Külekci, Fast Packed String Matching for Short Patterns (2012).** [Author preprint](https://arxiv.org/abs/1209.6449). Uses packed SSE operations for short-pattern search. Demonstrates that fewer scalar character operations alone are an insufficient comparison against hardware-assisted searching. Scope is single-pattern algorithms, not a direct many-rule solution; treat as a component baseline, not evidence of multi-pattern superiority.

5. **Wang et al., Hyperscan: A Fast Multi-pattern Regex Matcher for Modern CPUs (NSDI 2019), §§3–5.** [USENIX paper](https://www.usenix.org/system/files/nsdi19-wang-xiang.pdf). Integrates literal matching with decomposed finite automata, avoiding repeated full-regex work, and develops SIMD/bit-parallel string matching. Short literals and excessive extracted literals are explicit performance hazards. This is the strongest whole-engine competitor; a standalone filter comparison cannot establish superiority over its composed execution.

6. **aho-corasick 1.1.4, packed Teddy implementation design.** [Versioned project documentation](https://docs.rs/crate/aho-corasick/1.1.4/source/src/packed/teddy/README.md). Explains SIMD nibble lookups, fingerprint buckets, cross-block alignment and exact verification. This is a non-AC matching path despite the crate name. Common fingerprints make verification dominate; larger fingerprints improve selectivity at additional scanning cost. Relevant practical competitor for small/moderate sets, with bucket fanout a key scaling constraint.

7. **Bille, Gørtz, Vildhøj, Wind, String Matching with Variable Length Gaps (2011 preprint; journal 2012), §3.** [Author preprint/PDF](https://arxiv.org/abs/1110.2893). Maintains merged reachable ranges and discards expired ranges as literal occurrences arrive in endpoint order. Useful positional-join model without enumerating the Cartesian product of candidate positions. The paper uses AC for occurrence discovery: replacing that stage is an engineering adaptation, and its overall bound does not automatically transfer to hash witnesses.

8. **Graf and Lemire, Binary Fuse Filters: Fast and Smaller Than Xor Filters (2022).** [Author paper](https://arxiv.org/abs/2201.01174). Static approximate membership can cheaply reject q-words before accessing a larger exact postings table. It does not return anchor IDs, positions, or establish a pattern match. Its extra hashing/probes must cost less than avoided exact-table accesses; small cache-resident tables may already be cheaper. Construction failure must retry or fall back, never silently omit keys.

9. **Mitzenmacher, A Model for Learned Bloom Filters and Optimizing by Sandwiching (NeurIPS 2018).** [Publisher paper](https://papers.neurips.cc/paper/7328-a-model-for-learned-bloom-filters-and-optimizing-by-sandwiching.pdf). A backup membership filter preserves every known key rejected by the model. False-positive behavior depends on the query distribution. For this project, learning could safely rank anchor choices or filter a fully enumerated witness set with backup; a learned classifier over arbitrary future event records cannot inherit that finite-key guarantee.

## Coverage proof and limits of the proposal

The following is our derivation. Select a contiguous anchor window of length `q+s-1` starting at anchor offset `a`; register `(anchorID,a+r)` for every `r=0..s-1`. For an occurrence beginning at text offset `p`, exactly one residue `r` makes `p+a+r` divisible by `s`. The sampled q-word lies entirely inside the occurrence, so its complete posting list includes that anchor. Candidate start is `sampleOffset-(a+r)`; bounds-check and compare the complete anchor. For `q=s=8`, a 15-byte window covers all eight phases. Length bands 7/3/1 similarly support q=s=4/2/1. This proves candidate completeness, not final condition truth.

Retain all colliding postings and exact-verify them. Handle arbitrary buffer alignment, embedded NULs, tails, overlapping matches, duplicate anchors, and modifiers consistently. An empty/optional branch cannot require an absent anchor. Every accepted alternative needs a covered witness; arbitrary classes, nocase and wide encodings require equivalent coverage, explicit variants, or an unsupported result. Do not treat unsupported as negative.

Witness order is sample-offset order, not necessarily anchor-end order. Interval joins relying on ordered occurrences need sorting or another proof. Boolean reachability can merge compatible intervals; reporting every span, count or provenance needs richer state. Joining components from different alternatives must not invent a match.

## Continue/kill predictions to freeze before measurement

- **Best case:** long, diverse mandatory anchors, mostly-negative small records, one active width band. Scan cost is roughly `n/s` table probes plus candidate verification; memory includes up to `s` postings per anchor. Compare end-to-end against current scanner, packed SIMD matching, and a scalar block-hash baseline on identical semantics.
- **Short-anchor hazard:** active strides 8,4,2,1 require about `1.875n` probes if scanned separately. One short common mandatory anchor can erase the intended saving. Keep portfolios separated in results; kill broad applicability if realistic mixed rules collapse to bytewise work.
- **Collision/fanout hazard:** shared or periodic q-words can trigger many anchor verifications at every sample. Count probes, postings visited, exact comparisons and bytes rechecked. A correct implementation needs an explicit worst-case strategy; never truncate postings or accept partial checking as negative.
- **Join hazard:** repeated component literals and broad gaps can dominate filter savings. Compare ordered range propagation with naive pair enumeration on dense near-misses; kill the naive join if work grows quadratically with occurrences.
- **Probabilistic/learned add-ons:** defer unless profiles show exact-table misses dominate and a compact front filter measurably avoids them. Prediction alone must never remove a required witness.
- **Operational gate:** the already-frozen [README](README.md) controls: 10% primary latency improvement plus its correctness, family and guardrail requirements. The earlier generic 20% suggestion is superseded by that pre-measurement protocol, not by observed results. No SOTA claim follows from this study.

**Speculative next composition:** choose a different rare mandatory q-word for each alignment residue, potentially from different mandatory components. Soundness requires proving that every accepted occurrence, in every residue and alternative, exposes its selected word on the sampled grid; preserve offsets and exact verification. This may resemble known spaced-seed or sampling constructions. Novelty and benefit are unestablished; no implementation or speed claim is proposed.
